將 AI agent 與 Foundry IQ 整合

在本練習中，您將使用 Microsoft Foundry portal 建立與 Foundry IQ 整合的 agent，以從 knowledge base 搜尋並擷取資訊。您將建立 search resource、使用範例資料設定 knowledge base、在 portal 中建置 agent，然後從 Visual Studio Code 連線至 agent，以程式方式與它互動。

提示：本練習使用的程式碼以 Microsoft Foundry SDK for Python 為基礎。您也可以使用 Microsoft .NET、JavaScript 和 Java 的 SDK 開發類似的解決方案。請參閱 Microsoft Foundry SDK client libraries 以取得詳細資訊。

本練習大約需要 45 分鐘才能完成。

注意：本練習使用的部分技術仍處於預覽階段或積極開發中。您可能會遇到非預期的行為、警告或錯誤。

必要條件

開始本練習之前，請確認您已具備以下條件：

  • 具有 Azure subscription ，且有權限建立 AI 資源
  • Visual Studio Code 已安裝於本機
  • Python 3.13 已安裝
  • Git 已安裝於本機
  • 基本熟悉 Microsoft Foundry portal 與 Python 程式設計

* 目前尚不支援 Python 3.14：部分相依套件沒有 3.14 的版本。本實驗已使用 Python 3.13.12 測試。

建立 Foundry project

首先，使用新的 Foundry 體驗建立 Foundry project。

  1. 在網頁瀏覽器中開啟 Foundry portal ，網址為 https://ai.azure.com ，並使用您的 Azure 認證登入。關閉首次登入時開啟的任何提示或快速入門窗格。

    重要：請確認 New Foundry 切換開關已設為 On ，以便在本實驗中使用更新後的使用者介面。

  2. 切換至 New Foundry後，系統會要求您選取 project。在下拉式清單中選取 Create a new project.
  3. 在 Create a project 對話方塊中，輸入有效的 project 名稱（例如 agent-iq-lab).
  4. 確認或設定 project 的下列選項：
    • Foundry resource: 建立新的 Foundry resource，或選取現有的 resource
    • Subscription: 您的 Azure subscription
    • Resource group: 建立或選取 resource group
    • Location: 選取任何可用的 region*

    * 部分 Azure AI 資源受限於區域性的 model quota。如果在本練習後續步驟中超出 quota 上限，您可能需要在不同的 region 中建立另一個 resource。

  5. 選取 Create 並等待 project 建立完成。這可能需要幾分鐘。
  6. project 建立完成後，您會看到 project 首頁。

建立 agent

  1. 在首頁上選取 Build 索引標籤，然後在 Agents 索引標籤上選取 Create agent.
  2. 使用具描述性的名稱建立 agent，例如 product-expert-agent.

建立 agent 時，系統會部署預設 model（例如 gpt-5）。agent 建立完成後，您會看到 agent playground，且系統已自動為您選取該預設 model。

設定您的資料與 Foundry IQ

現在，您將設定使用 Foundry IQ 搜尋 knowledge base 的 agent。

  1. 首先，為 agent 提供下列指示：

    You are a helpful AI assistant for Contoso, specializing in outdoor camping and hiking products. 
You must ALWAYS search the knowledge base to answer questions about our products or product 
catalog. Provide detailed, accurate information and always cite your sources.
If you don't find relevant information in the knowledge base, say so clearly.
  2. 選取 Save 以儲存目前的 agent 設定。
  3. 接著，在 Knowledge 區段中，展開 Add 下拉式清單，並選取 Connect to Foundry IQ.
  4. 在 Connect to Foundry IQ 視窗中選取 Connect to an AI Search resource ，然後選取 Create new resource ，這應會開啟建立 resource 的對話方塊。
  5. 使用下列預設設定建立 search resource：
    • Resource name: 全域唯一的名稱
    • Subscription: 您的 Azure subscription
    • Resource group: 使用與 project 相同的 resource group
    • Region: 與 project 相同的位置
    • Pricing tier：Free （若可用；否則選擇 Basic）

    重要：如果您在此處建立 resource 時遇到任何問題，或看到警告訊息 This region is at capacity，請選取表單底部的連結，改從 Azure portal 建立。

現在，您將上傳產品資訊的範例文件，供 Foundry IQ 連線使用。

  1. 開啟新的瀏覽器索引標籤，並瀏覽至以下網址，下載產品資訊範例檔案： https://github.com/MicrosoftLearning/mslearn-ai-agents/raw/main/Labfiles/04-integrate-agent-with-foundry-iq/data/contoso-products.zip
  2. 解壓縮 zip 檔案，應會得到 3 份 PDF，詳細說明 Contoso 的產品。
  3. 開啟新的索引標籤，並瀏覽至 Azure portal，網址為 https://portal.azure.com。在頂端搜尋列中搜尋 Storage accounts ，並選取 Storage accounts （位於服務區段）。
  4. 使用下列設定建立 storage account：
    • Subscription: 您的 Azure subscription
    • Resource group: 使用與 project 相同的 resource group
    • Storage account name: 唯一的 storage account 名稱
    • Region: 與 project 相同的位置
    • Primary service: Azure Blob Storage or Azure Data Lake Storage
    • Performance: Standard
    • Redundancy: Locally-redundant storage (LRS)
  5. 建立完成後，移至您建立的 storage account，並選取 Upload （位於頂端列）。
  6. 在 Upload blob 刀鋒視窗中，建立新的 container，名稱為 contosoproducts.
  7. 瀏覽至從 zip 檔案解壓縮出的檔案，選取全部 3 份 PDF 檔案，然後選取 Upload.
  8. 檔案上傳完成後，瀏覽至您建立的 search service。
  9. 在左側窗格中，於 Security + networking > Keys下，選取 Both 作為 API Access control 的設定，並確認選取。完成後，讓 Azure Portal 索引標籤保持開啟，返回 Foundry portal 索引標籤並重新整理頁面。
  10. 確認您位於 Knowledge 頁面，選取 Create a knowledge base，選擇 Azure Blob Storage 作為 knowledge source，然後選取 Connect.
  11. 使用下列設定來設定 knowledge source：
    • Name: ks-contosoproducts
    • Description: Contoso product catalog items
    • Storage account name: 選取您的 storage account
    • Container name: contosoproducts
    • Authentication type: API Key
    • Content extraction mode: minimal
    • Embedding model: 選取可用的已部署 model，可能是 text-embedding-3-small
    • Chat completions model: 選取可用的已部署 model，可能是 gpt-5
  12. 選取 Create.
  13. 在 knowledge base 建立頁面上，選取 gpt-5 model（位於 Chat completions model 下拉式清單），其他欄位保留預設值。
  14. 選取 Save knowledge base，然後重新整理瀏覽器，確認 knowledge source 狀態為 active。如果尚未變成此狀態，請稍等一分鐘，再重新整理頁面，直到狀態變更。
  15. 選取返回按鈕以返回 Knowledge 頁面，然後選取 Manage 連結（位於 Connection 下拉式清單旁）。
  16. 向下捲動至 Connected resources，您應該會在此看到 search service。選取該列，找到 Authentication 區段。
  17. 選取 Key authentication ，然後選取 Edit authentication.
  18. 讓對話方塊保持開啟，返回 Azure portal 索引標籤，此時應仍停留在 search service 的 Keys 頁面。將其中一個 key 複製到 Foundry 中的對話方塊，然後選取 Save.

您的 Foundry IQ 設定現在應已完成。

在 playground 中測試 agent

從程式碼連線之前，請先在 portal playground 中測試 agent。

  1. 返回 Build > Agents 頁面，並選取您建立的 agent。
  2. 在 agent 頁面中，您應該會看到已選取的 playground 索引標籤。找到 knowledge 區段並新增 Foundry IQ，選取您建立的 connection 和 knowledge base。
  3. 嘗試下列測試查詢，確認 agent 能從 knowledge base 擷取資訊：
    • What types of tents does Contoso offer?
    • Tell me about which backpacks are available in XL.
    • What camping accessories are available?
  4. 檢閱回應，並注意：
    • agent 會提供來自 knowledge base 的具體資訊
    • 回應可能包含來源文件的引文或參考資料
    • agent 會持續專注於產品資訊

  5. 您也可以嘗試在 Preview agent 中與 agent 互動，以獲得更精緻的 webapp 體驗。

  6. 在 agent 詳細資訊頁面中，找到下列資訊並複製至記事本（稍後您將需要這些資訊）：
    • Agent name：這是您建立時使用的名稱（product-expert-agent)
    • Project endpoint：可在 project 設定或首頁中找到

設定 agent，要求工具呼叫必須經過核准

當您在 portal 中建立 agent 時，其 Foundry IQ（knowledge）工具預設會 不經 核准就執行。為了確保應用程式能檢閱並控制每一次 knowledge base 查詢，您將使用 Foundry Toolkit for VS Code 擴充功能，將 agent 改為在使用工具前要求核准。

注意：Foundry portal 目前未提供變更此核准行為的設定，因此您將改從 Foundry Toolkit 擴充功能進行設定。

  1. 在 Visual Studio Code 中選取 Extensions （位於左側窗格），或按下 Ctrl+Shift+X，然後在市集中搜尋 Microsoft 提供的 Foundry Toolkit for VS Code 擴充功能，並選取 Install （如果尚未安裝）。

    注意：此擴充功能目前列出的名稱為 Foundry Toolkit，但部分 VS Code 標籤、命令或較舊的螢幕擷取畫面可能仍使用 AI Toolkit這個名稱。在本實驗中，請將這些名稱視為同一個擴充功能體驗。

  2. 選取 Foundry Toolkit 圖示（位於側邊欄），若系統提示，請登入 Azure 帳戶。

    注意：如果無法透過 Foundry Toolkit 擴充功能登入，您可能需要選取 Azure 擴充功能。在該處登入後，再返回 Foundry Toolkit 以存取您的資源。

  3. 在 Microsoft Foundry Resources下，選擇 Set Foundry Project 並選取您先前建立的 project。
  4. 選取 Agents 區段。在開啟頁面上的 Prompt Agents 索引標籤下，選取您的 product-expert-agent agent，以開啟 Agent Builder 視窗。

  5. 在 Tools 區段中，您應該已能看到一個工具，其名稱由 kb-knowledgebase 前綴加上唯一 ID 組成（例如 kb-knowledgebase677-7w5fj）。這就是 Foundry IQ knowledge base 工具；當您在 portal 中連線至 Foundry IQ 時，系統會自動新增此工具。

    注意：agent 會列出不只一個工具。Foundry portal 預設會為新 agent 新增 Web search 工具，您也可能看到獨立的 Azure AI Search 工具。當 agent 搜尋您的 knowledge base 時，實際呼叫的是 kb-knowledgebase... 工具，因此在其他工具上設定核准不會產生作用。

  6. 選取省略號（…）圖示（位於 kb-knowledgebase... 工具上），然後選取 Configure 並選取 Never auto-approve tools，儲存變更後，在 playground 面板頂端選取 Deploy 以儲存您的變更。

現在，agent 每次使用 Foundry IQ 搜尋 knowledge base 時都會要求核准，接下來您將完成的 client 應用程式會處理這些要求。

從應用程式連線至 agent

現在，您將建立 Python 應用程式，以程式方式與 agent 互動。GitHub repository 中已提供起始檔案，協助您快速開始。

準備在 Visual Studio Code 中開發應用程式

現在，使用 Visual Studio Code 開發應用程式。應用程式的程式碼檔案已提供於 GitHub repo 中。

  1. 啟動 Visual Studio Code，並開啟 command palette（Shift+Ctrl+P）。接著搜尋並執行 Git: Clone 命令，將 https://github.com/MicrosoftLearning/mslearn-ai-agents repo 複製至本機資料夾（可選擇任何資料夾）。

  2. repository 複製完成後，在 Visual Studio Code 中開啟該資料夾。

    注意：如果 Visual Studio Code 顯示快顯訊息，要求您信任正在開啟的程式碼，請按一下 Yes, I trust the authors 選項以繼續。

  3. 若系統提示，請等待支援 repo 中 Python 程式碼 project 的其他檔案安裝完成。

    注意：如果系統提示您安裝建置與偵錯所需的資產，請選取 Not Now.

  4. 在 Explorer 窗格中，展開 Labfiles/04-integrate-agent-with-foundry-iq/Python 資料夾。

    提供的檔案包含應用程式程式碼、組態設定，以及 agent client 的起始程式碼。

設定應用程式選項

  1. 在 Visual Studio Code 中，於 Labfiles/04-integrate-agent-with-foundry-iq/Python 資料夾中開啟 .env 組態檔案。
  2. 在程式碼檔案中，將 your_project_endpoint 預留位置替換為您 project 的 endpoint（從 Foundry portal 中 project 的 Home 頁面複製），並確認 AGENT_NAME 變數已設為您的 agent 名稱（應為 product-expert-agent).
  3. 替換預留位置後，儲存檔案。

完成 agent client 程式碼

提示：新增程式碼時，請務必保持正確的縮排。請以註解的縮排層級作為參考。

  1. 在 Visual Studio Code 中，於 Labfiles/04-integrate-agent-with-foundry-iq/Python 資料夾中開啟 agent_client.py 程式碼檔案。
  2. 檢閱已提供的起始程式碼，包括：
    • import 陳述式與組態載入
    • 以下的 send_message_to_agent() 函式結構
    • 以下的 display_conversation_history() 函式
    • 主程式迴圈

  3. 找到第一個 TODO 註解，並新增下列程式碼，以連線至 project、取得 OpenAI client、擷取 agent，並建立新的 conversation：

    提示：請注意維持正確的縮排層級。

    # Connect to the project and agent
credential = DefaultAzureCredential(
    exclude_environment_credential=True,
    exclude_managed_identity_credential=True
)
project_client = AIProjectClient(
    credential=credential,
    endpoint=project_endpoint
)

# Get the OpenAI client
openai_client = project_client.get_openai_client()

# Get the agent
agent = project_client.agents.get(agent_name=agent_name)
print(f"Connected to agent: {agent.name} (id: {agent.id})\n")

# Create a new conversation
conversation = openai_client.conversations.create(items=[])
print(f"Created conversation (id: {conversation.id})\n")

  4. 找到第二個 TODO 註解（位於 send_message_to_agent() 函式內），並新增下列程式碼，以傳送訊息及處理回應，包括 MCP 核准要求：

    # Add user message to the conversation
openai_client.conversations.items.create(
    conversation_id=conversation.id,
    items=[{"type": "message", "role": "user", "content": user_message}],
)

# Store in conversation history (client-side)
conversation_history.append({
    "role": "user",
    "content": user_message
})

# Create a response using the agent
response = openai_client.responses.create(
    conversation=conversation.id,
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
    input=""
)

# Loop until a response has no pending approval requests (zero, one, or many)
while True:
    approval_requests = [
        item for item in (getattr(response, "output", None) or [])
        if getattr(item, "type", None) == "mcp_approval_request"
    ]

    if not approval_requests:
        break

    approval_items = []
    for approval_request in approval_requests:
        print(f"[Approval required for: {approval_request.name}]\n")
        print(f"Server: {approval_request.server_label}")

        # Show the tool call arguments for transparency
        import json
        try:
            args = json.loads(approval_request.arguments)
            print(f"Arguments: {json.dumps(args, indent=2)}\n")
        except Exception:
            print(f"Arguments: {approval_request.arguments}\n")

        approval_input = input("Approve this action? (yes/no): ").strip().lower()
        approved = approval_input in ['yes', 'y']
        print("Approving action...\n" if approved else "Action denied.\n")

        approval_items.append({
            "type": "mcp_approval_response",
            "approval_request_id": approval_request.id,
            "approve": approved
        })

    # Send the approval decisions and fetch the next response
    openai_client.conversations.items.create(
        conversation_id=conversation.id,
        items=approval_items
    )

    response = openai_client.responses.create(
        conversation=conversation.id,
        extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
        input=""
    )

    注意：agent 不一定每次都要求核准，有時也可能在同一輪對話中要求核准多個工具呼叫。持續執行迴圈，直到 approval_requests 為空，就能正確處理這兩種情況。

  5. 新增程式碼後，儲存檔案。

  6. 檢閱目前使用 conversations API 管理與 agent 互動的程式碼，其中：
    • conversation 會被建立，並透過其 ID 追蹤
    • 使用者訊息會透過以下方式新增至 conversation： conversations.items.create()
    • 回應會透過以下方式產生： responses.create() ，並附帶 agent 參考
    • MCP 核准處理：當 agent 需要存取 Foundry IQ 時，會要求核准，並在回應輸出中傳回一個或多個 mcp_approval_request 項目
    • 程式碼會持續執行迴圈，提示您核准或拒絕每個待處理的要求，直到 agent 傳回沒有未完成核准要求的回應（也涵蓋從未需要核准的情況）
    • 每次核准／拒絕後，都會將一個 mcp_approval_response 新增至 conversation，並產生新的回應
    • agent 會根據您的核准決定，從 Foundry IQ 擷取資訊

測試整合

現在，您將執行應用程式，並測試 agent 從 knowledge base 擷取資訊的能力。

  1. 在 Visual Studio Code 中，為 Labfiles/04-integrate-agent-with-foundry-iq/Python 資料夾開啟整合式終端機：在資料夾上按一下滑鼠右鍵，然後選取 Open in Integrated Terminal.

  2. 首先，建立 virtual environment 並安裝相依套件。

    python -m venv labenv
./labenv/Scripts/activate
pip install -r requirements.txt

  3. 在終端機窗格中輸入下列命令，以登入 Azure。

    az login

    注意：在大多數情況下，僅使用 az login 就足夠了。不過，如果您在多個 tenant 中擁有 subscription，可能需要使用 –tenant 參數指定 tenant。請參閱 使用 Azure CLI 以互動方式登入 Azure 以取得詳細資訊。

  4. 系統提示時，請依照指示在新索引標籤中開啟登入頁面，並輸入提供的驗證碼與您的 Azure 認證。接著在命令列完成登入程序；若系統提示，請選取包含 Foundry resource 的 subscription。

  5. 在終端機窗格中執行應用程式：

    python agent_client.py

  6. 應用程式啟動後，使用下列查詢測試 agent：

    查詢 1－產品類別：

    What types of outdoor products does Contoso offer?

    系統提示核准時，輸入 yes 以允許 agent 搜尋 knowledge base。觀察 agent 如何從 knowledge base 中的多份文件擷取資訊。

    查詢 2－特定產品詳細資訊：

    Tell me about the weatherproof features of your tents.

    核准要求，並注意 agent 如何從帳篷目錄提供具體詳細資訊。

    查詢 3－產品比較：

    What's the difference between your daypacks and expedition backpacks?

    核准要求，並觀察 agent 如何綜合背包指南中的資訊。

    查詢 4－配件與加購品：

    What camping accessories would you recommend for a weekend hiking trip?

    核准要求，並觀察 agent 根據 knowledge base 提供建議的能力。

    查詢 5－後續問題：

    How much do those items typically cost?

    請注意 agent 如何保留先前查詢的對話 context。

  7. 輸入 history 以檢視完整的對話記錄。

  8. 輸入 quit 以結束測試。

檢閱結果

請考量 agent 回應的下列面向：

  • MCP 核准流程：agent 每次需要存取 knowledge base 時，都會要求核准，讓您能控制外部工具的使用
  • 正確性：agent 會直接提供來自 knowledge base 文件的資訊
  • 引文：agent 可能包含來源參考或文件 ID
  • context 感知能力：agent 會記住對話中先前的訊息
  • Grounding：當 agent 無法在 knowledge base 中找到相關資訊時，會明確指出
  • 錯誤處理：應用程式能妥善處理錯誤與連線問題

  • 使用產品資訊文件建置 knowledge base
  • 在 portal 中設定啟用 Foundry IQ 的 agent
  • 使用 Python SDK，從 Visual Studio Code 連線至 agent
  • 實作具備 MCP 核准處理、對話記錄和錯誤處理功能的 client 應用程式
  • 測試 agent 從 knowledge base 擷取並綜合資訊的能力，並由使用者控制外部工具存取的核准

這示範了如何將 AI agent 與 Foundry IQ 整合，建立能從企業 knowledge base 搜尋並擷取資訊，同時保留對話 context 的智慧應用程式。

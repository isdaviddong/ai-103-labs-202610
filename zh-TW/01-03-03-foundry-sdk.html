建立 generative AI 聊天應用程式

在此練習中，您將使用 OpenAI SDK 與 Responses API 建立聊天應用程式，連線至 Microsoft Foundry 專案中部署的 model。

此練習大約需要 45 分鐘。

注意：此練習使用的部分技術仍處於預覽階段或持續開發中。您可能遇到非預期的行為、警告或錯誤。

先決條件

開始此練習之前，請確認您具備下列項目：

  • 有效的 Azure subscription
  • Visual Studio Code 已安裝
  • Python 版本 3.13.xx 已安裝*
  • Git 已安裝並完成設定
  • Azure CLI 已安裝

* Python 3.14 已推出，但部分相依套件尚未針對此版本編譯。此實驗已使用 Python 3.13.12 成功測試。

建立 Microsoft Foundry 專案

Microsoft Foundry 使用專案來組織開發 AI 解決方案所需的 model、resource、資料及其他資產。

  1. 在網頁瀏覽器中，開啟 Microsoft Foundry portal ，網址為 https://ai.azure.com ，開始建置；使用您的 Azure 認證登入。關閉首次登入時開啟的任何提示或快速入門窗格。

  2. 如果尚未啟用，請在頁面頂端的工具列中啟用 New Foundry 選項。接著，如果出現提示，請以唯一的名稱建立新專案；展開 Advanced options 區域，為您的專案指定下列設定：
    • Foundry resource: 使用 resource 的預設名稱（通常為 {project_name}-resource）
    • Subscription: 您的 Azure subscription
    • Resource group: 建立或選取 resource group
    • Region：選取 AI Foundry recommended 的任一區域，請參閱 此清單
  3. 等候專案建立完成，然後檢視其首頁。

部署 model

接下來，讓我們部署聊天應用程式將使用的 model。

  1. 現在您已準備好探索 model。在 Discover 頁面中，選取 Models 索引標籤，檢視 Microsoft Foundry model catalog。
  2. 在 model catalog 中搜尋 gpt-5.2.
  3. 檢閱 model card，然後使用預設設定部署它。
  4. Model 部署完成後，會在 model playground 中開啟；您可以視需要在該處測試。

取得 endpoint

您需要 endpoint，才能從用戶端應用程式連線至 model。在此練習中，我們將使用 OpenAI SDK 與 model 聊天，並使用 Azure OpenAI endpoint 搭配 Entra ID authentication 進行連線。

注意：除了 Entra ID authentication，您也可以使用專案的 API Key。只要可行，都應優先使用 Entra ID authentication。

  1. 在功能表列中，選取 Home 頁面。

  2. 記下該頁面顯示的 Azure OpenAI Endpoint 。

    提示：在此練習中，您會使用 Azure OpenAI Endpoint ， 而不是 project endpoint！

建立與 model 聊天的用戶端應用程式

現在您已部署 model，可以使用 OpenAI SDK 與 Responses API，開發與它聊天的應用程式。

從 GitHub 取得應用程式檔案

開發聊天應用程式所需的初始應用程式檔案已提供於 GitHub repo。

  1. 開啟 Visual Studio Code。

  2. 開啟命令選擇區（Ctrl+Shift+P），並使用 Git:clone 命令，將 https://github.com/microsoftlearning/mslearn-ai-studio repo 複製到本機資料夾（任一資料夾皆可），然後開啟它。

    系統可能會提示您確認是否信任作者。

準備應用程式設定

  1. 在 Visual Studio Code 中，檢視 Extensions 窗格；若尚未安裝，請安裝 Python 擴充功能。

  2. 在 Command Palette中，使用命令 python:select interpreter。然後根據您安裝的 Python 3.13，建立新的 Venv 環境。

    提示：如果系統提示您安裝相依套件，可以安裝 requirements.txt 檔案中列出的套件，該檔案位於 /labfiles/foundry-chat/python/chat-app 資料夾；如果沒有安裝也沒關係，我們稍後會安裝！

  3. 在 Explorer 窗格中，瀏覽至包含應用程式程式碼檔案的資料夾： /labfiles/foundry-chat/python/chat-app。應用程式檔案包括：
    • .env （應用程式設定檔）
    • requirements.txt （需要安裝的 Python 套件相依項目）
    • chat-app.py （聊天應用程式的程式碼檔案）
    • chat-async.py （非同步版本應用程式的程式碼檔案）

  4. 在 Explorer 窗格中，以滑鼠右鍵按一下包含應用程式檔案的 chat-app 資料夾，然後選取 Open in integrated terminal （或在 Terminal 功能表中開啟終端機，並瀏覽至 /labfiles/foundry-chat/python/chat-app 資料夾）。

    注意：在 Visual Studio Code 中開啟終端機會自動啟用 Python 環境。您可能需要允許系統執行 script。

  5. 確認終端機已在 labfiles/foundry-chat/python/chat-app 資料夾中開啟，且具有 (.venv) 前綴，表示您建立的 Python 環境已啟用。

  6. 執行下列命令，安裝 OpenAI SDK、Azure Identity 及其他必要套件：

     pip install -r requirements.txt

  7. 在 Explorer 窗格的 labfiles/foundry-chat/python/chat-app 資料夾中，選取 .env 檔案以開啟它。接著更新設定值，加入 Azure OpenAI Endpoint 及指派給 gpt-5.2 model 的 deployment 名稱。

    提示：從 Foundry portal 的專案首頁複製 Azure OpenAI Endpoint （不是 project endpoint！），並在 MODEL_DEPLOYMENT 設定中輸入指派給您的 deployment 的完整正確名稱。

    儲存修改後的設定檔。

使用 ChatCompletions API 與 model 聊天

其中， ChatCompletions API 是建置大型語言 model 用戶端應用程式的成熟方式，已獲廣泛採用。

  1. 在 Explorer 窗格的 labfiles/foundry-chat/python/chat-app 資料夾中，選取 chat-app.py 檔案（不是 chat-async.py）以開啟它。

  2. 檢閱現有程式碼。您將新增程式碼，使用 OpenAI SDK 存取 model。

    提示：將程式碼新增至程式碼檔案時，務必維持正確的縮排。

  3. 在程式碼檔案頂端的現有 namespace 參考下方，找到註解 Import namespaces ，並新增下列程式碼，匯入使用 OpenAI SDK 所需的 namespace：

    # import namespaces
from openai import OpenAI
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

  4. 在 main 函式中，請注意已提供從設定檔載入 endpoint 與 key 的程式碼。接著找到註解 Initialize the OpenAI client，並新增下列程式碼，建立 OpenAI API 的 client：

    # Initialize the OpenAI client
token_provider = get_bearer_token_provider(
     DefaultAzureCredential(), "https://ai.azure.com/.default"
)
    
openai_client = OpenAI(
     base_url=azure_openai_endpoint,
     api_key=token_provider
)

  5. 在 main 函式中，請注意已提供持續要求使用者輸入 prompt、直到使用者結束應用程式為止的程式碼。在此迴圈中，找到 Get a response 註解，並新增下列程式碼：

    # Get a response
completion = openai_client.chat.completions.create(
     model=model_deployment,
     messages=[
         {
             "role": "system",
             "content": "You are a helpful AI assistant that answers questions and provides information."
         },
         {
             "role": "user",
             "content": input_text
         }
     ]
)
print(completion.choices[0].message.content)

    請注意， ChatCompletions API 使用 JSON 格式的 messages 集合封裝對話。這些訊息通常包含 system prompt ，用來向 model 提供指示，以及 user prompt ，其中包含使用者的輸入。

  6. 儲存程式碼檔案的變更。接著，在終端機窗格中使用下列命令登入 Azure。

     az login

    注意：在大多數情況下，只使用 az login 就足夠。不過，如果您的 subscription 分散在多個 tenant 中，可能需要使用 –tenant 參數指定 tenant。詳情請參閱 使用 Azure CLI 以互動方式登入 Azure 。

  7. 出現提示時，依照指示登入 Azure。然後在命令列中完成登入程序，檢視包含您的 Foundry resource 的 subscription 詳細資料（必要時加以確認）。

  8. 登入後，輸入下列命令執行應用程式：

    python chat-app.py

    程式應會在終端機中執行（如果沒有，請解決所有錯誤後再試一次）。

  9. 出現提示時，輸入下列 prompt：

     Tell me about the ELIZA chatbot.

    稍待片刻後，應用程式應會回應一些關於 1960 年代建立的 ELIZA chatbot 的資訊。

  10. 輸入 prompt quit 以結束應用程式。

使用 Responses API 與 model 聊天

雖然 ChatCompletions API 廣泛使用，但它正逐漸被較新的 Responses API 取代。讓我們更新程式碼，改用此 API。

  1. 在 chat-app.py 程式碼的 main 函式中，將註解 Get a response 下方的程式碼替換成下列使用 Responses API 的程式碼。

    # Get a response
response = openai_client.responses.create(
             model=model_deployment,
             instructions="You are a helpful AI assistant that answers questions and provides information.",
             input=input_text
)
print(response.output_text)

    請注意，語法更簡單：system message 指派給 instructions 參數，而 user prompt 指派給 input 參數。

  2. 儲存程式碼的變更，並在終端機窗格中重新執行應用程式（python chat-app.py).

  3. 出現提示時，輸入與先前相同的 prompt：

     Tell me about the ELIZA chatbot.

    稍待片刻後，應用程式應會再次回應一些關於 ELIZA chatbot 的資訊。

  4. 輸入下列 prompt，嘗試繼續對話：

     How does it compare to modern LLMs?

    應用程式的回應應會顯示它不理解「it」指的是什麼。對話的 context 已遺失。我們將修正這個問題。

  5. 輸入 prompt quit 以結束應用程式。

新增對話追蹤

若要保留對話的 context，必須在每個新請求中包含對先前回應的參考。

  1. 在 chat-app.py 程式碼的 main 函式中，找到註解 Loop until the user wants to quit，並在其 上方 新增下列程式碼（也就是在迴圈之前 ）：

    # Track responses
last_response_id = None

  2. 將註解 Get a response 下方的程式碼修改為下列程式碼，以在請求中傳送上一個 response ID，然後取得新的 response ID，以供下次加入。

    # Get a response
response = openai_client.responses.create(
             model=model_deployment,
             instructions="You are a helpful AI assistant that answers questions and provides information.",
             input=input_text,
             previous_response_id=last_response_id,
)
print(response.output_text)
last_response_id = response.id

    使用此技巧，您可以傳送上一個回應的 ID，保留 context。您也可以實作更複雜的邏輯，傳送任一先前回應的 ID，將對話導向其他方向，或恢復先前的對話串。

  3. 儲存程式碼的變更，並在終端機窗格中重新執行應用程式（python chat-app.py).

  4. 出現提示時，輸入與先前相同的 prompt：

     Tell me about the ELIZA chatbot.

    稍待片刻後，應用程式應會再次回應一些關於 ELIZA chatbot 的資訊。

  5. 輸入下列 prompt，嘗試繼續對話：

     How does it compare to modern LLMs?

    這次，應用程式應會回應 ELIZA chatbot 與現代 LLM 的比較。回應可能很長，而應用程式會等到從 model 收到完整回應後才顯示，因此可能看起來沒有反應。接下來我們將修正這個問題！

  6. 輸入 prompt quit 以結束應用程式。

實作 streaming 回應

若要處理較長的回應，可以使用 streaming ，在完整文字傳回之前就開始處理部分回應。

  1. 在 chat-app.py 程式碼的 main 函式中，將註解 Get a response 下方的程式碼替換成下列程式碼，它會使用 streaming：.

    # Get a response
stream = openai_client.responses.create(
             model=model_deployment,
             instructions="You are a helpful AI assistant that answers questions and provides information.",
             input=input_text,
             previous_response_id=last_response_id,
             stream=True
)
for event in stream:
     if event.type == "response.output_text.delta":
         print(event.delta, end="")
     elif event.type == "response.completed":
         last_response_id = event.response.id
print()

    請注意， stream=True 參數會建立 streaming 回應，其中的 events 會在每個新的資料區塊（或 delta）準備好可供處理時發生。

  2. 儲存程式碼的變更，並在終端機窗格中重新執行應用程式（python chat-app.py).

  3. 出現提示時，輸入與先前相同的 prompt：

     Tell me about the ELIZA chatbot.

    稍待片刻後，應用程式應會開始回應一些關於 ELIZA chatbot 的資訊。每個資料區塊傳回時，回應應會逐步顯示。

  4. 輸入下列 prompt，嘗試繼續對話：

     How does it compare to modern LLMs?

    同樣地，回應應會逐步顯示。

  5. 輸入 prompt quit 以結束應用程式。

使用非同步 API

OpenAI SDK 提供非同步選項，可在使用長時間執行的 model 或 agent 作業時，提高應用程式的回應能力。

  1. 在 Explorer 窗格的 labfiles/foundry-chat/python/chat-app 資料夾中，選取 chat-async.py 檔案（不是 chat-app.py）以開啟它。

  2. 檢閱現有程式碼。您將新增程式碼，使用 OpenAI SDK 的 async API 存取 model。

    提示：將程式碼新增至程式碼檔案時，務必維持正確的縮排。

  3. 在程式碼檔案頂端的現有 namespace 參考下方，找到註解 Import namespaces ，並新增下列程式碼，匯入使用 OpenAI SDK 所需的 namespace：

    # import namespaces for async
import asyncio
from openai import AsyncOpenAI
from azure.identity.aio import DefaultAzureCredential, get_bearer_token_provider

  4. 在 main 函式中，請注意已提供從設定檔載入 endpoint 與 key 的程式碼。接著找到註解 Initialize an async OpenAI client，並新增下列程式碼，建立 OpenAI API 的 client：

    # Initialize an async OpenAI client
credential = DefaultAzureCredential()
token_provider = get_bearer_token_provider(
 credential, "https://ai.azure.com/.default"
)

async_client = AsyncOpenAI(
     base_url=azure_openai_endpoint,
     api_key=token_provider
)

  5. 在 main 函式中，請注意已提供持續要求使用者輸入 prompt、直到使用者結束應用程式為止的程式碼。在此迴圈中，找到 Await an asynchronous response 註解，並新增下列程式碼：

    # Await an asynchronous response
response = await async_client.responses.create(
             model=model_deployment,
             instructions="You are a helpful AI assistant that answers questions and provides information.",
             input=input_text,
             previous_response_id=last_response_id
)
assistant_text = response.output_text
print("Assistant:", assistant_text)
last_response_id = response.id

    此程式碼會等候 model 的非同步回應。

  6. 在 main 函式末端的 finally 區塊中，找到註解 Close the async client session ，並新增下列程式碼，關閉非同步 client：

    # Close the async client session
 await credential.close()

  7. 儲存程式碼檔案的變更。接著在終端機窗格中，使用下列命令執行程式：

    python chat-async.py

    程式應會在終端機中執行（如果沒有，請解決所有錯誤後再試一次）。

  8. 出現提示時，輸入下列 prompt：

     Tell me about the Turing test.

    稍待片刻後，應用程式應會回應一些關於 Turing test 的資訊。

  9. 輸入 prompt quit 以結束應用程式。

摘要

在此練習中，您使用 OpenAI SDK 以及 ChatCompletions 與 Responses API，為部署在 Microsoft Foundry 專案中的 generative AI model 建立用戶端應用程式。您透過追蹤對話的 context 自訂 model 行為，並實作 streaming，提供能即時回應的聊天體驗。

清理

如果您已完成 Microsoft Foundry 的探索，請刪除此練習中建立的 resource，避免產生不必要的 Azure 費用。

  1. 開啟 Azure portal ，檢視您部署此練習所用 resource 的 resource group 內容。
  2. 在工具列上，選取 Delete resource group.
  3. 輸入 resource group 名稱，並確認您要刪除它。
